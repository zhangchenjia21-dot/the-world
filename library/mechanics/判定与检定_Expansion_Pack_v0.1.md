# 判定与检定｜Expansion Pack v0.1（过渡包）

> [!abstract] 这份拓展包是什么
> 一套**临时的概率裁定层**。启用它，当游戏里一个行动的结果不确定、且失败有真实代价时，成败不再全凭 GM 一口气 narrate 过去，而是一次公开、可查验的 **d20 检定**：掷一个二十面骰，加上由人物事实裁定出的加值，与难度（DC）比较，结果对玩家完全明示。
>
> 它是过渡包：在正式判定系统（与世界观、能力体系深度耦合的专属机制）建成之前，先用这套接近 DND 的通用框架保证"判定存在、判定公平、判定可见"。正式系统落地后本包被 supersede 并归档。

> [!important] 启用方式
> 这是一份可选拓展包，只有在玩家明确选择启用后才进入游戏。未启用时，GM 按世界包与其它机制包直接叙述裁定即可，不使用本包的骰子与 DC 术语。

---

## 1. 这个包为游戏增加什么

**增加的体验**：

- **判定存在**：高风险行动有真实的成败概率。攀爬、潜行、说服、急救、追踪——不再因为 GM 写得顺就自动成功；
- **判定公平**：骰子是`tools/掷骰.mjs`产生的真随机，不是模型"想"出来的数字。玩家赢要赢得起，输要输得服；
- **判定可见**：点数、加值、DC、成败全部明示。玩家能看懂"为什么成、为什么败"，并据此调整下一次策略；
- **风险有差异**：同一目标的不同做法，不应只是换一段文案后继续掷同一个 DC。准备方式、对象人格、情报、暴露程度与失败代价应真实改变风险结构。

**它拒绝什么**：

- "掷骰流水线"——不是每个行动都过检定（见第 2 节三不掷）；
- "所有方案只是不同皮肤"——有意义的选择应体现不同的可行性、难度、优势/劣势与失败代价；
- 属性表重造——不引入六维属性、技能列表、等级经验；加值从已有人物事实裁定（见第 5 节）；
- 暗骰——玩家看不见点数的检定等于没有检定；
- 失败挡死剧情——失败产生代价与转折，不产生"卡关"（见第 7 节）。

**它不拥有什么**：检定命中之后的具体后果（伤势、名望变化、关系变化、资源消耗）归各领域机制包与世界语义；战斗中的位置、节奏、压力归《战斗核心》。本包只回答一个问题：**这次尝试成了没有。**

正式原则：

> **A meaningful choice should differ in risk structure, not only narrative direction.**
>
> **有意义的选择不仅结果方向不同，风险结构也应不同。**

---

## 2. 何时检定：三不掷

同时满足两个条件才检定：**结果不确定**，且**失败有真实代价**。具体三不掷：

1. **必然成立不掷**——以人物的能力与处境，这件事没有失败的可能（常人平地走路、行家做家常手艺）；
2. **必然不成立不掷**——差距悬殊到骰子救不回来（新兵当面骗过识破过他的老兵；要求一个人物在没有任何实质变化时直接背弃已经冻结的核心底线）。GM 直接叙述不成，或让局面说话；
3. **无代价不掷**——失败了也可以毫无成本地立刻重来的事，直接叙述完成即可。

一次检定应覆盖一个有意义的行动意图，不把"翻窗进去"拆成敏捷、力量、运气三掷。

**骰子只裁定真实存在的不确定性，不负责抹掉人物人格、世界事实或已经成立的因果。**

---

## 3. 检定流程

```text
1. GM 与玩家明确：尝试什么、成功得到什么、失败付出什么
2. GM 先判断这条行动路线的风险结构：
   - 是否需要检定
   - 固有难度（DC）
   - 情境态势（优势 / 普通 / 劣势）
   - 失败代价
3. GM 裁定人物加值（第 5 节）
4. 调用 tools/掷骰.mjs 掷骰
5. 向玩家明示：骰面、加值、总计、DC、优势/劣势理由、成败
6. 按第 7 节把成败写进叙事与世界后果
```

**禁止模型自称随机**。"我掷了一个 14"不被接受；骰子只能来自 `tools/掷骰.mjs` 的真实输出。

### 3.1 同一目标，不同方案应先比较风险结构

当玩家面对一个真正的 meaningful choice，GM 不应先问"这几个选项分别要掷什么骰"，而应先问：

```text
这条路线本身容易还是难？
当前情境对它有利还是不利？
失败到底会损失什么？
它是否暴露身份、消耗资源、伤害关系或让局势升级？
```

同一目标的几种合法方案可以出现完全不同的结构：

```text
路线 A：不掷骰，但放弃主动权
路线 B：DC 15 + 优势，失败会打草惊蛇
路线 C：DC 20 + 劣势，成功收益更大，失败会造成政治关系恶化
路线 D：行动本身必然能做成，但真正的风险发生在后续反应，不在"能不能做"上
```

这比让四条路线都落到"d20 +3 对 DC15"更重要。

### 3.2 玩家先选行动，GM 再公开机械裁定

行动建议仍以世界内自然语言表达，不默认把玩家界面变成：

```text
A【DC15·优势】
B【DC20·劣势】
```

玩家应先按角色目标、风险判断和世界理解决定"怎么做"。选定后，GM 再公开本次检定的 DC、加值、优势/劣势及失败 stakes，让规则透明但不把 RPG 退化成菜单算题。

---

## 4. 难度（DC）

| 难度 | DC | 直觉 |
|---|---|---|
| 简单 | 10 | 有点挑战的常人事 |
| 中等 | 15 | 需要真本事的行当活 |
| 困难 | 20 | 行家也要捏把汗 |
| 极难 | 25 | 名动一方的壮举 |
| 近乎不可能 | 30 | 说书人都不敢这么编 |

GM 可依情境在相邻档之间微调 ±2，不必拘泥五档。

### 4.1 DC 不是唯一的难度轴

不要用一个 DC 数字承担所有风险差异。

- **DC**主要表达：这件事本身有多难；
- **优势/劣势**主要表达：当前方法与情境是否明显有利或不利；
- **失败代价**表达：输了以后世界会付出什么；
- **三不掷**表达：这件事是否根本存在值得随机裁定的不确定性。

如果两个方案的难度体验明显不同，优先检查这四个轴是否真的不同，而不是机械地把 DC 从 15 调成 16。

---

## 5. 加值裁定

加值不是查表，而是 GM 对**当前人物相关事实**的裁定，主要依据《人物能力与技艺》《身体状态核心》及角色档案中已有的事实：

| 量级 | 含义 |
|---|---|
| +0 | 常人水准，未经训练 |
| +2 | 练过、有经验 |
| +4 | 以此为业的行家 |
| +6 | 顶尖好手，稀有 |
| ±1~2 | 伤情、装备、环境等临时情境修正，可叠加 |

NPC 同样适用。检定只读取**该角色世界内事实**——知识边界规则不变，穿越者系统的鉴定信息、GM 私有信息不构成任何角色的加值理由。

加值主要回答"这个人本身有多会做这件事"。如果优势来自**这一次的方法、对象、准备和环境**，优先用第 6 节优势/劣势表达，不要把所有情境都塞成零碎 +1/+2。

---

## 6. 优势与劣势

就一条简化规则：

- **优势**（情境明显有利：以逸待劳、情报充分、专业对口、方法精准击中对象的关注点）→ 掷两个 d20 取高；
- **劣势**（情境明显不利：带伤、摸黑、工具将就、方法明显踩中对象的戒备或厌恶）→ 掷两个 d20 取低；
- 优势与劣势不叠加、不累计，同时存在则互相抵消为普通一掷。

### 6.1 优势 / 劣势必须真的参与路线差异

优势/劣势不是偶尔出现的装饰词，而是表现**同一人物换一种做法，风险就明显不同**的主要工具之一。

例如：

- 提前掌握可靠账册去说服一个重证据的人 → 可以有优势；
- 对同一个人只靠夸赞与空泛承诺 → 可能普通甚至劣势；
- 对重面子的人公开逼迫 → 可能劣势；私下给台阶 → 可能优势；
- 对直来直往的人绕弯试探 → 可能劣势；把条件与底线直接摊开 → 可能优势。

这不是"NPC 有一个隐藏弱点标签"。判断必须来自已经成立的人格、关系记忆、身份、利益、恐惧、义务和当前处境。

### 6.2 人格与关系可以改变检定，但不能被检定覆盖

人物是谁，应该真实改变社交行动的难度结构；但骰子不能让人物突然不再是自己。

```text
NPC 人格 / 当前目标 / 关系历史 / 利益与义务
+
玩家选择的沟通方式与筹码
↓
是否可行
DC
优势 / 普通 / 劣势
失败代价
```

如果玩家试图让 NPC 直接跨过一个当前明确、稳定、没有被新事实动摇的核心底线，通常属于第 2 节的**必然不成立**，不是"给一个很高 DC，天然 20 就人格反转"。

正式原则：

> **Dice decides uncertainty. Dice does not erase character.**
>
> **骰子裁定不确定性，不抹除人物。**

---

## 7. 成败语义

- **成功**：行动意图达成。若总计低于 DC 5 以内擦线成功，GM 可附带小代价（complication）；
- **失败**：意图不达成，且**世界继续转动**——失败必须产生新的局面、代价或信息（惊动了犬巡、暴露了来路、得罪了中人），而不是原地重试；
- **大成功 / 大失败**：骰面天然 20 / 天然 1 时，GM 可给出超出预期的收益或代价，但应克制，不是每次都戏剧化。

任何成败后果若是 durable change，照常按后台维护规则落盘。

### 7.1 失败改变局面，不等于所有失败都一样

"失败不挡死剧情"不能被理解成"反正失败了 GM 都会把玩家送到下一个场景，所以路线风险差不多"。

不同做法的失败应尽量保留其独有代价：

- 偷听失败 → 身份暴露 / 对方加强戒备；
- 正面交涉失败 → 关系恶化 / 条件变差；
- 花钱疏通失败 → 资源损失 / 中间人知道你的意图；
- 绕路侦查失败 → 时间推进 / 目标转移；
- 强攻失败 → 伤亡 / 战术位置恶化。

因此：

> **失败改变局面，而不是关闭游戏；行动方式决定失败把局面改变成什么样。**

这两句话必须同时成立。

## 8. 掷骰工具用法

```bash
node tools/掷骰.mjs 1d20+4        # 常规检定：骰面+修正
node tools/掷骰.mjs 1d20+4 adv    # 优势：掷两骰取高
node tools/掷骰.mjs 1d20+4 dis    # 劣势：掷两骰取低
node tools/掷骰.mjs 3d6           # 多骰（伤害、群体判定等临时用途）
```

工具输出即唯一有效骰面。叙事中引用结果时原样转述，不修饰、不重掷——玩家明确说"重掷 / 我不接受这个失败"属于 Recovery / Regenerate 语义，由玩家发起，不由 GM 悄悄修正。

## 9. 与其它机制包的边界

```text
判定与检定（本包）  → 这次尝试成了没有
战斗核心            → 战斗中的位置、节奏、压力、攻防语义
身体状态核心        → 命中之后身体付出什么
人物能力与技艺      → 加值裁定的事实来源
人物 / 关系语义      → 社交对象的人格、边界、记忆与自主性
穿越与系统          → 系统自身的任务 / 货币语义，不干预骰子
```

各领域包对同一场面有规定时，**先按领域包铺情境，再用本包定成败，最后回领域包结算后果**。

人物与关系语义不是"判定以后再应用"的后处理器。对于社交行动，它们在掷骰前就决定：这件事是否可行、DC 是多少、有没有优势/劣势，以及失败会伤到什么。

## 10. 过渡定位与退役

本包是 Stage 0 / TW-01 期间的过渡裁定层。退役条件：

- 正式判定系统（与世界观、能力成长、机制深度耦合的专属判定机制）设计并启用；
- 或真实试玩证明 d20 框架本身损害游戏体验，经玩家裁定更换。

退役时本文件移入归档，启用本包的游戏在 COMPOSITION.md 中更新配置，已发生的检定历史不回溯改写。
