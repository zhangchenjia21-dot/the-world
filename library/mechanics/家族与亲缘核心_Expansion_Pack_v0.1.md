# 家族与亲缘核心｜Expansion Pack v0.1

> [!abstract] 一句话定位
> **`EP-KINSHIP-CORE｜家族与亲缘核心` 是跨世界通用的家族身份与亲缘结构事实唯一归属者：维护人物之间已经成立的源亲缘关系、可选的长期家系对象、家系分支、谱系来源、亲缘主张与证据边界，并为关系、组织、名望、政治、法律及世界专用系统提供有界的亲缘事实。**
>
> 它不把“家人”误写成“关系好”，不把“家族”误写成“组织”，不把血缘事实自动等同于法律身份、政治继承权或公众认知，也不建立通用“血统纯度”数值。

> [!important] 设计核心
> **保存产生亲缘结构的源事实，尽量不保存可以稳定推导的复合亲属关系。**
>
> 例如父母、收养、正式认亲和家系归属可以是正式结构；兄弟姐妹、祖孙、堂表亲、姻亲称谓、共同祖先和世代距离默认由程序按当前问题计算。

---

# 0. 已确认设计方向

本 v0.1 冻结以下方向：

1. 正式中文名称为 **家族与亲缘核心**；`EP-KINSHIP-CORE` 保持稳定资产 ID。
2. “家族”可以是长期世界对象，但不是每一组父母子女都自动生成一个家族对象。
3. 家族对象只拥有家系身份与谱系结构，不拥有财富、领地、政治权力、组织职位、社会名望或法律制度。
4. 一个人可以同时与多个家系建立不同类型的关联；不存在“一个人物只能有一个 family_id”的产品语义。
5. 亲缘不等于血缘；可以存在生物亲缘、收养亲缘、正式认定亲缘，以及由婚姻产生的可推导姻亲结构。
6. 婚姻作为双方人际关系事实仍由 `EP-RELATIONSHIP-ROMANCE-CORE` 拥有；Kinship 不保存第二份“已婚=true”。
7. 收养成功后的养父母—养子女结构由 Kinship 拥有；双方感情仍由 Relationship 拥有。
8. 义父、义子、结拜兄弟等只有在世界规则真正赋予其长期亲缘身份时才进入 Kinship；普通“情同手足”仍只是 Relationship。
9. 生物亲缘不能因为一句“断绝关系”被删除；正式家族承认、收养或拟制亲属关系可以按世界规则发生、终止或改变。
10. 姓氏、名字、家族名称与家系归属分离；改姓、改名不自动改写亲缘。
11. 父亲 / 母亲是文化或展示语义；底层亲本关系不把所有世界写死成唯一的“父+母”二元模型。
12. 生育、怀孕、生产过程不属于本 Core；本 Core 只接收已经形成的人物与亲本事实。
13. 死亡不删除亲缘；历史人物可以继续作为祖先存在于谱系中。
14. 家系分支可以是正式长期结构；相对世代距离默认由谱系计算。
15. 父系、母系、长幼可以描述或计算；嫡庶、长子继承、合法性、绝嗣等文化制度不作为通用默认规则。
16. 不建立通用“血统纯度”字段；具体世界、政治、魔法、神术等系统可以读取祖先路径后自行解释。
17. 真实亲缘、谱系主张、法律承认、社会传闻、个人知识必须分层。
18. 家谱是亲缘事实的按需展示，不是第二事实源；玩家看到的家谱必须遵守信息边界。
19. 未知亲属可以先作为未知谱系位置存在；一旦成为具体可持续互动人物，必须拥有稳定人物身份。
20. 大型家系图允许长期增长，但普通回合和局部问题只读取当前必要的谱系切片。

# 1. 职责边界

## 1.1 本 Core 唯一回答的问题

> **“人物或家系之间现在与历史上成立了怎样的亲缘结构；这些结构来自什么源关系；哪些家族 / 家系身份与分支已经成立；某个谱系主张有什么依据；在当前问题下应该读取哪一小段亲缘图？”**

## 1.2 本 Core 负责

- 可选的 Family / Lineage 长期身份；
- 家系当前名称、历史名称与来源关系；
- 家系分支；
- 生物学亲本 / 后代结构；
- 收养亲本 / 后代结构；
- 世界规则正式认定的亲缘关系；
- 人物与家系之间的正式家系关联；
- 亲缘关系来源、成立时间、结束时间（仅适用于可变化关系）；
- 祖先 / 后代路径；
- 谱系主张；
- 与谱系主张直接相关的证据引用与可信来源边界；
- 已确认、未知、存在候选、存在争议等亲缘真相状态的语义表达；
- 对确定谱系的程序化查询与局部投影；
- Family / Kinship player-safe projection；
- 与 Relationship / ORG / Reputation / Politics / Law / Character / Magic / Divine 等系统的亲缘事实交接。

## 1.3 本 Core 明确不负责

- Sentiment / Trust / Respect / Attachment / Romantic Attraction；
- 婚姻作为双方人际承诺本身；
- Organization Membership / Role / Rank / Internal Authority；
- Public Reputation / 社会评价；
- 政治权力、王位、统治承认或继承结果；
- 法律程序、合法性判断、继承法或法定亲子身份的最终裁决；
- Pregnancy / Fertility / Reproduction simulation；
- Character Personality / Capability；
- 遗传能力、魔法血统效果、神血授权、种族能力；
- 财富、领地、产业、人口、税收；
- 军团、战役、军权；
- 公共传闻系统或全局知识系统；
- RNG / Dice / Program Judge / Formal Outcome / Atomic Commit / Save / Restore authority；
- G9-03 尚未冻结的最终机器字段、Schema、Compiler 或 Creator 协议。

# 2. 家族对象与亲缘网络

## 2.1 亲缘网络是基础

最小系统不要求先建立 Family Entity 才能存在亲缘。

```text
人物 A
→ 源亲缘关系
→ 人物 B
```

普通现代家庭、临时出现的小家庭可以只依赖人物之间的亲缘源关系。

## 2.2 家族 / 家系对象是可选的长期对象

当世界真的需要一个跨世代、可寻址的家系身份时，可以建立 Family / Lineage 对象，例如：

- 古老世家；
- 王室家系；
- 贵族 House；
- 跨世代宗族血缘共同体；
- 吸血鬼血族；
- 魔法家系；
- 具有稳定世界身份的现代家族。

禁止：

```text
任何父母 + 子女
→ 自动创建一个新的 Family Entity
```

是否需要 Family Entity 取决于世界和玩法是否需要长期寻址。

## 2.3 Family != Organization

```text
曹氏作为亲缘家系
→ Kinship

曹氏形成的政治集团 / 宗族管理机构
→ ORG / Politics
```

同一个现实共同体可以同时存在：

```text
Family / Lineage Identity
↕ explicit reference
Organization Identity
```

二者可以成员高度重合，但不能共享同一份 Role / Rank / Membership / Internal Authority 状态。

# 3. 源亲缘关系与派生关系

## 3.1 保存源关系

本 Core 优先长期保存真正产生结构的源关系：

- 生物亲本关系；
- 收养亲本关系；
- 世界规则正式建立的拟制 / 认定亲缘；
- 人物与家系的正式关联；
- 家系分支来源；
- 外部正式婚姻事实的引用（只作姻亲计算来源，不复制婚姻状态）。

## 3.2 默认不保存所有复合称谓

以下通常是派生结果：

- 兄弟姐妹；
- 祖父母 / 曾祖父母；
- 孙辈；
- 叔侄 / 舅甥；
- 堂兄弟 / 表姐妹；
- 岳父母 / 姐夫 / 嫂子等姻亲称谓；
- 最近共同祖先；
- 相对世代距离；
- 某人属于第几代后裔。

```text
源边数量增长
<<
全部 pairwise 亲属称谓数量增长
```

这样纠正一条亲本事实时，不需要同步改写大量重复关系。

## 3.3 确定性谱系计算优先交给程序

对于已经确定的图结构：

- 两人亲缘路径；
- 最近共同祖先；
- 祖先 / 后代集合；
- 相对世代距离；
- 某家系相关分支；

优先由程序执行图查询，再把有限结果交给模型解释。

> **确定的谱系图计算不应为了“让 AI 推理”而加载整个家谱。**

# 4. 亲本、收养与正式认亲

## 4.1 亲本关系保持跨世界中立

底层语义是“亲本 / 后代”，而不是强制所有世界使用唯一的父亲 + 母亲模型。

世界与人物信息可以进一步显示：父亲、母亲、双亲、第一亲本或其它文化称谓。

允许：

- 单亲；
- 多亲本；
- 非性别化亲本；
- 特殊奇幻繁衍后的已成立亲本结构。

但“创造者制造了一个生命”不会自动变成亲本；只有世界事实真正承认其为亲缘关系时才进入 Kinship。

## 4.2 收养

正式成立的收养关系可以产生养父母—养子女结构。

```text
收养事实成立
→ Kinship 记录养亲结构
→ 可触发 Relationship / Law / Politics / Reputation 等下游
```

Kinship 不负责定义某国法律需要什么手续才能收养。

## 4.3 正式认亲 / 拟制亲属

“义父、义子、结拜兄弟”等不按字面自动进入 Kinship。

只有当世界规则、正式仪式或已提交事件使其成为长期家族结构时，才形成正式认定亲缘。

普通“情同手足”“视如己出”仍由 Relationship 表达。

---

# 5. 婚姻与姻亲边界

现有 `EP-RELATIONSHIP-ROMANCE-CORE` 继续拥有：

> 婚姻作为 A 与 B 之间成立的人际关系与共同承诺事实。

Kinship 不建立第二份婚姻真相。

正确分层：

```text
Relationship：婚姻成立 / 结束
↓ typed Event / bounded read
Kinship：按当前世界规则形成 / 结束可推导姻亲结构
```

绝大多数岳父、姐夫、嫂子等关系不独立持久化，而由婚姻源事实 + 亲本结构按需计算。

世界是否认为婚姻会让人物“正式加入配偶家族”，由 World Pack /正式家系事件决定，不能作为通用默认规则。

---

# 6. 多家系关联

一个人物可以同时拥有不同意义的家系关联，例如：

- 出生家系；
- 收养家系；
- 正式认入家系；
- 当前被某家系承认；
- 通过婚姻与另一家系产生关联但未正式加入。

因此：

```text
出生于某家系
!=
当前唯一家系身份
!=
与某家系存在姻亲关联
```

姓氏、显示名称不能代替这些关系。

---

# 7. 姓名、家系名称与稳定身份

## 7.1 姓氏 != 家系身份

同姓可能无亲缘；同一家系可能跨越多个姓氏；人物可以改姓、赐姓、使用化名或没有姓氏。

因此不得通过显示姓名临时猜家族归属。

## 7.2 家系改名

家系可以改名，但稳定身份不变：

```text
Stable Family Identity
├─ current name
└─ historical aliases
```

历史名称只用于显示、查询和来源，不产生新 Owner。

---

# 8. 家系分支、分裂与合并

## 8.1 家系分支

家系可以拥有长期分支，例如主系、旁支、长房、二房或世界自定义支系。

这些只是谱系结构；ORG 的部门 / Branch 是另一种事实。

## 8.2 从分支形成新家系

如果某支后来长期成为独立家族：

```text
原家系
→ 来源 / 分出事件
→ 新 Family Identity
```

新家系保留其来源祖先与原家系关系。

## 8.3 “合并”不是数据库吞并

两个历史家系不会因为联姻或政治合并就删除旧身份。

如果世界形成真正的新家系，则创建新的 Family Identity 并保存来源；如果只是联盟或婚姻，不创建伪造的“合并家系”。

---

# 9. 出生、死亡与历史连续性

## 9.1 出生

本 Core 不模拟怀孕或生产。

只有当具体人物已经正式成为世界中的稳定人物后，才可以把已确定的亲本 / 家系结构绑定到该人物。

## 9.2 死亡

死亡不会删除亲缘：

```text
人物死亡
!= 祖先关系失效
```

历史人物继续保留在谱系中，但普通回合不因此自动加载历史祖先。

---

# 10. 真实亲缘、主张、法律、公众与个人知识

这是本 Core 的关键边界。

## 10.1 真实亲缘结构

Kinship 维护当前可被系统视为权威的亲缘结构。

但不强迫世界必须知道全部答案。允许：

- 已确认；
- 当前未知；
- 存在多个候选；
- 存在争议；
- 已排除某些候选。

这些是语义要求，不提前冻结 G9-03 机器枚举。

## 10.2 谱系主张与证据

例如：

> “X 声称自己是前任国王的私生子。”

这首先是一个谱系主张，不等于修改真实亲本。

可以关联：

- 书信；
- 族谱；
- 出生记录；
- 证人证词；
- 信物；
- 魔法 / 神术鉴定结果；
- 其它世界事实引用。

Kinship 只保存“该证据支持 / 反对哪个亲缘主张”的结构与来源，不复制证据正文，也不自己成为调查判定系统。

## 10.3 法律承认

```text
真实生物亲缘
!= 法律亲子身份
!= 继承资格
```

法律身份与合法性由未来 Law Owner；王位、统治承认和政治继承由 Politics / Law 共同按各自职责处理。

Kinship 只提供所需谱系事实。

## 10.4 社会传闻 / 公众相信什么

“公众认为 X 是某人的孩子”不等于真实亲缘，也不等于 Reputation 本身。

在通用 Knowledge / Information / Rumor Owner 尚未正式冻结前，Kinship 只提供谱系主张与 player-safe 事实，不建立第二套全社会认知状态。

Reputation 可以在公众认知形成后处理“人们因此如何评价目标”。

## 10.5 个人知识

后台知道亲缘真相，不代表角色知道。

玩家 / NPC 可见家谱、人物详情和 Narrative 只能读取该角色当前允许获得的亲缘投影。

---

# 11. 家族承认、断亲与事实不可逆边界

## 11.1 允许自由尝试

玩家可以尝试：

- 认亲；
- 声称某人为父母 / 子女；
- 请求收养；
- 正式收养；
- 认义父 / 义子；
- 宣布断绝关系；
- 要求加入某家系；
- 否认某段谱系；
- 调查身世。

这些 Action / Intent 不是白名单；自由语言永远允许合理尝试。

## 11.2 声称亲缘 != 亲缘成立

单方面“你是我儿子”最多形成主张 / 社会事件候选，不能直接写入真实生物亲缘。

## 11.3 断绝关系不删除生物来源

```text
“从此我没有你这个儿子”
→ Relationship 可能破裂
→ Family recognition 可能变化
→ Law / Politics 可能产生后果
→ Biological Parentage 保留
```

同理，认祖归宗可以改变家族承认，不会凭仪式创造不存在的生物学祖先。

---

# 12. 关系变化与真相纠错

必须区分：

## A. 关系本身在世界中发生变化

例如：

- 正式收养成立；
- 收养关系依法 /按世界规则结束；
- 正式认亲成立或撤销；
- 家系承认发生改变；
- 外部婚姻变化导致当前姻亲结构变化。

这些拥有真实有效期。

## B. 对既有真相的认识发生变化

例如：

> 大家一直以为 A 是生父，后来证据证明 B 才是生父。

不应解释成“A 曾经在生物学上真的是父亲，后来变成 B”。

这是认知 /证据 /权威事实确认发生变化，而非生物来源在历史中被改写。

---

# 13. 文化中立与世界扩展

Core 提供结构语言；World Pack 提供文化解释。

## 13.1 通用 Core 可以表达

- 亲本 / 后代；
- 收养；
- 正式认定亲缘；
- 家系身份；
- 家系分支；
- 姻亲来源；
- 出生顺序；
- 祖先路径；
- 谱系主张与证据。

## 13.2 World Pack /下游制度解释

可以进一步定义：

- 父系 / 母系 / 双系社会的重要性；
- “宗亲”“外戚”“House”“cadet branch”等文化称谓；
- 嫡庶；
- 非婚生身份；
- 长子继承；
- 家门绝嗣；
- 禁婚范围；
- 特定认亲仪式；
- 哪些家族关联具有政治或法律效力。

这些都不是通用 Core 的默认宇宙规则。

## 13.3 不建立通用“血统纯度”

Kinship 只提供祖先 / 后代路径。

具体系统可以读取：

```text
祖先结构
→ 世界 / Character / Magic / Divine / Politics 自己解释
```

例如龙裔能力、神血资格、王室意识形态都不由 Kinship 自己计算成一个“纯度百分比”。

# 14. 家谱与玩家体验

家谱不是第二份数据库，而是按需投影。

不同目的需要不同切片：

```text
查看我的近亲
→ 当前人物附近的少量亲缘

查共同祖先
→ 两条必要祖先路径

查继承争议
→ 当前候选相关谱系分支

浏览古老家系
→ 分支 / 世代分页或按需展开
```

玩家看到的家谱只显示 player-safe / known 信息。

本 Core 不在 G9-03 前冻结“必须存在一个家谱一级栏目”。它可以向人物详情、家族详情、信息视图或未来专用谱系视图提供数据。

---

# 15. 身世调查玩法

本 Core 不创建独立“身世调查掷骰器”。

推荐链：

```text
怀疑 / 谱系主张
↓
询问人物 / 搜索记录 / 观察遗物 / 调查地点 / 魔法或神术手段
↓
其它正式 Domain 产生证据 / 信息
↓
Kinship 更新谱系主张的证据结构
↓
满足正式确认条件时
→ Program / authoritative owner 提交亲缘事实更新
```

模型可以解释证据和提出结构化候选，但不得因为“证据看起来很多”就自行写入亲本真相。

# 16. 未知亲属与动态人物

## 16.1 未知谱系位置可以没有人物实体

例如：

> “生父未知。”

可以存在一个未解析亲本位置，而不需要生成“未知父亲 NPC”。

## 16.2 一旦具体可交互，就必须有稳定人物身份

如果剧情确认“阿伦可能是你的父亲”，阿伦必须先是稳定人物，再建立相关主张 / 亲缘关系。

## 16.3 运行中按需创造具体亲属

若背景只确定“存在一名失散姐姐”，剧情后来需要其登场：

```text
既有背景约束
↓
生成具体人物候选
↓
Program 校验年龄 / 时间 / 已有谱系 / 世界约束
↓
建立稳定 Game-local Character
↓
提交亲缘关系
↓
Narrative / Product 才能持续引用
```

这与当前 G9 的 Game-local canonical identity / materialization 原则一致，但本资产不冻结机器实现字段。

# 17. 与其它 Core 的职责接口

## 17.1 Relationship

```text
“他们是否相爱 / 信任 / 亲密 / 疏远”
→ Relationship

“他们是否是亲生父子 / 养母女 / 正式亲属”
→ Kinship
```

Family Bond 可以是 Relationship 的共同关系事实，但不能成为第二份亲缘来源。

婚姻由 Relationship 持有；Kinship 只读取其结构后果。

## 17.2 ORG

```text
家族 / 家系身份
→ Kinship

族长职位 / 家族管理机构 / 内部权限
→ ORG
```

Kinship 的 Family Branch 不等于 ORG Department。

## 17.3 Reputation

Kinship 提供已允许公开的家系 / 亲缘事实；Reputation 负责社会如何评价人物 / 家族。

“某人是王室后裔”与“大家因此尊敬他”不能合并成同一状态。

## 17.4 Politics / Law（未来）

Kinship 只提供：

- 与当前继承 /权力主张相关的祖先路径；
- 当前家系 / 分支事实；
- 已确认或争议的谱系状态；
- player-safe / authority-safe 必要证据引用。

谁拥有继承权、谁正式继位、谁被法律承认为合法子女，不由 Kinship 最终判断。

## 17.5 Character / Magic / Divine

亲缘事实可以成为下游输入，例如遗传特征、龙裔、神血、家族魔法传统，但结果由对应 Domain 拥有。

# 18. Runtime Context Contract｜内建

本 Core 从 v0.1 起按 `Runtime Context Contract Pattern v0.5` born-compliant。

## 18.1 路由简介

```text
ID: EP-KINSHIP-CORE
Name: 家族与亲缘核心
Scope: 家系身份、亲本/后代、收养、正式认亲、家系分支、谱系主张、祖先路径与家谱查询
Typical semantics: 父母 / 子女 / 祖先 / 后代 / 家族 / 家系 / 收养 / 认亲 / 身世 / 族谱 / 分支 / 共同祖先 / 亲缘争议
```

第一轮路由不携带整个家族名单或完整谱系。

## 18.2 当前输入直接激活

典型：

- 查询或声明人物之间的亲缘；
- 查看家族 / 家系 / 谱系；
- 收养、认亲、断亲、加入家系等尝试；
- 调查身世、讨论谱系主张；
- 查询共同祖先、后代、家系分支；
- 当前动作明确需要家族身份或亲缘事实。

## 18.3 状态强制相关

只有当前正式操作本身正在处理：

- 未完成的收养 / 认亲流程；
- 当前正在确认的谱系主张；
- 当前动作必须消费确定的亲缘约束；
- 当前已选中的家系 / 人物亲缘问题；

才由程序补入 Kinship。

人物“有父母、有家族”本身不会让 Kinship 每回合常驻模型上下文。

## 18.4 下游激活

```text
亲缘 / 家系 Formal Event
↓ typed handoff
Relationship / ORG / Reputation / Politics / Law / 其它 Domain
```

例如收养成立后才允许下游处理关系意义、法律身份或声望反应；路由阶段不提前加载所有潜在后果。

## 18.5 不加载条件

通常不加载详细 Kinship：

- 与家族无关的普通闲聊；
- 普通战斗、移动、物品操作；
- 仅仅因为角色存在家人；
- 只需要一个确定亲缘事实、程序可直接返回时；
- 后台人物死亡 / timer 等与当前亲缘问题无关的状态推进。

## 18.6 最小读取集

按问题读取：

```text
current target person(s) / family
+
必要源亲缘边
+
必要祖先 / 后代路径
+
当前相关家系分支
+
必要主张 / 证据引用
+
player-safe knowledge boundary
```

禁止默认读取全部家族成员、全历史或所有谱系争议。

## 18.7 模型真正需要处理的语义

模型适合：

- 理解非标准自然语言亲缘表达；
- 分析“认亲 / 断亲 / 视如己出”等开放语义属于主张、关系还是正式亲缘候选；
- 解释争议身世与证据含义；
- 把程序算出的亲缘路径转换成符合世界文化的自然语言；
- 生成结构化亲缘变更候选 / 澄清需求。

## 18.8 程序负责

程序 / authoritative Runtime 负责：

- 稳定人物 / 家系引用；
- 已提交亲本 / 收养 / 家系关联状态；
- 确定性图遍历；
- 祖先 / 后代 / 共同祖先 / 世代距离计算；
- 关系有效期；
- 结构完整性与循环 / 不可能关系校验；
- Formal Outcome；
- Game-local canonical change；
- Atomic Commit；
- Save / Restore / Branch / Recovery。

## 18.9 模型输出候选

模型最多提出：

- 亲缘查询意图；
- 亲缘关系候选；
- 家系关联候选；
- 谱系主张候选；
- 证据关联候选；
- 收养 / 认亲 / 断亲意图；
- 需要澄清的问题。

候选不等于真实亲缘成立。

## 18.10 交接与信息边界

Incoming 可以来自：

- Relationship 的婚姻事实；
- Character / World 的稳定人物引用；
- Investigation / Information 的证据结果；
- Magic / Divine 的合法鉴定结果；
- 未来 Law / Politics 的正式事件。

Outgoing 只提供当前职责所需的有界亲缘投影。

后台真实亲缘、未知父母候选、秘密收养、未公开谱系证据不得因为下游询问就自动泄露。

## 18.11 上下文成本

必须满足：

```text
Family Members 20 → 200 → 2000
ordinary unrelated Turn context ≈ stable

Genealogy depth 3 → 12 → 30 generations
local kinship query context ≈ bounded by query paths
```

上下文成本由当前问题涉及的节点、路径和争议数量决定，而不是全家谱规模。

## 18.12 功能层级

Kinship v0.1 是单 Core，不强制拆多个 Feature / Module。

未来若家谱浏览、谱系调查等形成独立可启停产品能力，应在真实 Runtime 证据后再模块化；本稿不提前制造模块层级。

## 18.13 后台程序推进

人物年龄增长、死亡状态等其它 Domain 变化不需要 Kinship 每 tick 调模型。

确定的派生亲属关系也不需要后台不断重算；按查询或受影响源关系变更时更新缓存 / 投影即可。

## 18.14 大型图投影

本 Core 的“Registry”风险主要不是 Definition 数量，而是长期增长的谱系图。

正确链：

```text
Whole Kinship Graph
→ current query target(s)
→ deterministic relevant path/subgraph selection
→ player-safe bounded genealogy slice
→ Model only if semantic explanation is needed
```

模型不负责在 2000 人家谱里自行搜索共同祖先。

## 18.15 有界但充分

不能为了缩短 Context 而丢掉：

- 当前查询涉及的人物身份；
- 决定关系成立的必要源边；
- 争议问题真正相关的候选与证据；
- 当前世界文化下解释称谓所需的最小规则；
- 信息边界。

## 18.16 叙事对象必须有真实引用

具体可持续互动的父母、兄弟姐妹、祖先后裔、家族成员一旦在当前时间线作为人物出现，必须拥有稳定人物引用。

“未知父亲”“失散姐姐”可以先作为未解析谱系位置 / 背景约束；模型不能仅凭一句叙事把一个没有身份的具体 NPC 永久加入家谱。

## 18.17 跨归属者有界拼接

例如继承问题未来可能需要：

```text
Kinship relevant lineage slice
+
Politics relevant claim projection
+
Law relevant rule projection
```

只拼接当前问题所需事实；Kinship 不复制政治 /法律状态。

## 18.18 结果门控的继续激活

例如正式收养：

```text
玩家提出收养
→ 相关 Domain 处理当前条件 / 程序确认
→ Formal Adoption Outcome 成立
→ Kinship 提交养亲结构
→ 再触发 Relationship / Law / Reputation 等下游
```

如果上游正式结果未成立，不预先假设“已经成为家人”。

# 19. 创作与运行绑定要求

未来 Creator 至少需要能让作者表达：

- 重要人物之间的源亲缘；
- 可选 Family / Lineage 身份；
- 家系分支与来源；
- 已知重要祖先 / 后代；
- 开局已知 / 隐藏 / 争议的谱系信息；
- 重要亲缘主张与证据入口；
- 哪些内容是世界文化解释而非通用 Core 规则。

Creator **不应该要求作者预先填写整个世界所有家谱**。

允许：

```text
重要锚点
+
必要近亲
+
关键家系
+
谱系约束 / 未知位置
↓
运行中按需扩展具体人物与分支
```

G9-03 前不冻结最终字段名、机器枚举、任意查询 DSL、Creator UI 控件或编译器格式。

# 20. 机制测试场景

## TS-01｜普通父子
A 是 B 的生物亲本。查询“B 的父亲是谁”。期待：读取单条必要源关系；不加载整个家族。

## TS-02｜兄弟关系推导
A 与 B 有共同亲本。期待：程序推导兄弟姐妹关系；不要求保存第二条兄弟关系事实。

## TS-03｜十二代祖先
玩家询问自己是否为十二代前人物 X 的后裔。期待：按问题读取必要祖先路径；不能用固定“三代窗口”错误裁掉相关信息。

## TS-04｜收养成立
正式收养完成。期待：养亲结构成立；Relationship 可独立形成亲密或疏远；生物亲本不被覆盖。

## TS-05｜断绝关系
父亲宣布断绝父子关系。期待：生物亲缘保留；家族承认 / Relationship / Law / Politics 根据正式结果分别处理。

## TS-06｜义兄弟
两人称兄道弟但无正式世界规则。期待：Relationship 可记录 Bond；Kinship 不自动建立兄弟源关系。

## TS-07｜正式结拜成为拟制亲属
世界规则认定正式结拜具有长期亲缘身份。期待：Formal Outcome 后形成 recognized kinship；仍不伪造 biological parentage。

## TS-08｜婚姻与岳父
A 与 B 结婚，B 的父亲是 C。期待：婚姻真相仍由 Relationship；“C 是 A 的岳父”按需推导；Kinship 不保存第二份婚姻状态。

## TS-09｜改姓
人物改姓。期待：人物名称变化；家系与亲本事实不自动改变。

## TS-10｜家族与组织并存
某世家同时有族长和执法机构。期待：家系身份 /谱系归 Kinship；族长职位 /内部权限归 ORG。

## TS-11｜秘密身世
后台真实父亲是 A，玩家角色相信 B。期待：玩家家谱不泄露 A；后台真相不因 Narrative 自动暴露。

## TS-12｜谱系主张
X 声称自己是国王私生子但证据不足。期待：形成 claim + evidence；不直接改真实亲缘 /继承权。

## TS-13｜未知父亲
背景只确定“生父未知”。期待：允许未解析亲本位置；不制造一个可交互的“未知父亲 NPC”。

## TS-14｜失散姐姐登场
背景确定有失散姐姐，剧情需要其具体出现。期待：先 materialize 稳定人物并校验年龄 /时间 /谱系，再绑定亲缘并进入 Narrative。

## TS-15｜家族分支独立
旁支长期独立为新家系。期待：新 Family Identity + 来源关系；旧家系历史不被删除。

## TS-16｜家族“合并”
两家联姻。期待：默认仍是两个家系 + 婚姻 /姻亲关系；除非世界正式形成新家系，否则不做数据库 merge。

## TS-17｜死亡祖先
祖先死亡三百年。期待：亲缘仍有效；普通当前回合不加载其详细历史。

## TS-18｜龙血能力
角色确有龙族祖先。期待：Kinship 只提供祖先路径；龙血能力由对应 Character / Magic / Theme 处理，不计算通用血统纯度。

## TS-19｜王位继承
两个候选都与前王有亲缘。期待：Kinship 返回相关谱系；谁继位由 Politics / Law，不由 Kinship Judge。

## TS-20｜2000 人家谱
玩家只问两个人的共同祖先。期待：程序先选必要路径；模型看 bounded slice，不加载 2000 人。

# 21. 回归禁区

- 不得建立万能“家族好感度”。
- 不得把 Family Entity 做成 Organization 的替代品。
- 不得通过姓氏猜亲缘。
- 不得把婚姻在 Relationship 与 Kinship 双写。
- 不得为每对人物永久保存全部可推导亲属称谓。
- 不得把“断亲”解释成删除生物亲本。
- 不得把谱系主张直接当成真实亲缘。
- 不得让后台真相绕过角色知识边界。
- 不得把继承资格和政治合法性归给 Kinship。
- 不得建立通用嫡庶、父系优先、长子继承或血统纯度规则。
- 不得因为家谱很大就把完整图送给模型。
- 不得让模型执行确定性图查询、RNG、Formal Outcome 或 State Commit。
- 不得让未知亲属自动变成没有稳定身份的具体 NPC。
- 不得在 G9-03 前发明 final machine schema / arbitrary genealogy query DSL。
